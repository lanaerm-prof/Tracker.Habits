# Ритм — трекер привычек

Персональный трекер привычек: web/PWA-приложение для одного пользователя.
Чистый HTML + CSS + JavaScript **без сборки и без зависимостей** — данные хранятся
в `localStorage` и переживают перезапуск сессии.

Оформление сделано по брендбуку: ржаво-красный акцент `#B83729` и бирюза `#8FB8B2`
на тёплых нейтральных тонах, шрифт **Manrope** (свой, без внешних CDN),
единый линейный набор значков, светлая и тёмная темы.
Весь основной UI (кнопки, плашки, поля) — бирюзовый; ржавый зарезервирован
за важным и акцентным.

## Запуск

Приложение — статический сайт. Нужен любой HTTP-сервер (для PWA и service worker
файл `file://` не подходит).

**Вариант 1 — файл запуска (Windows):**

```bat
start.cmd
```

**Вариант 2 — вручную:**

```bash
python -m http.server 8123
```

Затем откройте <http://127.0.0.1:8123/>.

Первый вход — вкладка **Регистрация** (email + пароль от 4 символов).
Учётная запись, привычки и история хранятся локально в браузере.

## Экраны (по ТЗ)

| Экран | Маршрут | Что есть |
|---|---|---|
| Вход / Логин | `#/` | логин/email, пароль, регистрация, валидация |
| Сегодня | `#/today` | дата, приветствие, крупное кольцо прогресса с % по центру, список привычек с чекбоксами, крупная серия, блок «Лучше, чем вчера», «перевод» величин (`320 страниц ≈ 2 книги`), состояния дня |
| Привычки | `#/habits` | фильтры **Активно / В архиве**, карточки: иконка, категория (чип → редактирование), периодичность, цель, серия, лучшая серия, счётчик оставшихся пропусков в месяце, % за 30 дней |
| Категории | `#/categories` | создание, переименование, удаление; 8 пресетов (Здоровье, Учёба и работа, Спорт и движение, Питание, Дом и быт, Вредные привычки, Творчество, Сон и отдых); заголовки групп в форме совпадают с пресетами; значки вместо буквенных аватарок; карточки — **галерея с горизонтальной прокруткой**; число привычек в каждой; блок «Без категории» |
| Создать / Редактировать | `#/habit/new`, `#/habit/<id>` | иконки и палитра из брендбука, категория (чипы + своя), периодичность, дни недели, напоминание, единица измерения, цель, **допустимые пропуски в месяц (0–31)**, архивирование, удаление с подтверждением |
| Календарь | `#/calendar` | месяц с отметками «выполнено/по плану» и подробная панель дня (правка истории за прошлые даты) |
| Статистика | `#/stats` | периоды 7/15/30 дней и «всё время», **единый блок графика с переключением «По дням / По категориям»**, отдельная **сетка выполнения за 12 недель** (тепловая карта переехала сюда), текущая и лучшая серия, лучший день/неделя/месяц, рейтинг успешных привычек, итоги в понятных величинах |
| Настройки | `#/settings` | имя, светлая/тёмная тема, ссылка на категории, уведомления + **время напоминания**, установка приложения, экспорт JSON, удаление всех данных, выход |

Навигация: **боковая панель** на ПК, **бургер-меню** на планшетах и мобильных.

## Функции финальной версии

* **Количественные цели** с человекочитаемыми переводами: страницы → книги,
  минуты → часы, миллилитры → литры, шаги → километры.
* **Пропуски под контролем**: у каждой привычки лимит пропусков в месяц,
  на экране «Привычки» видно «Осталось N пропусков» / «Пропущено N дней»,
  при превышении — отдельная подсказка.
* **Категории**: CRUD + пресеты, активность по категориям в статистике.
* **Уведомления**: вкл/выкл push и ежедневное время напоминания (по умолчанию 20:00).
* **Данные**: экспорт в JSON, полное удаление, подтверждения удаления привычки,
  категории, всех данных и разрушения серии.
* **PWA**: установка на устройство, офлайн-работа оболочки, адаптив без
  горизонтального скролла на 1920 / 1366 / 1024 / 820 / 768 / 414 / 360 px.
* **UX-состояния**: Empty, Loading (сплэш), Error (с кнопкой повтора), Completed,
  Incomplete, Archived, No statistics, First day, Long streak,
  Exceeded allowed misses.

### Тональность интерфейса

Короткие фразы без давления: «Начните с одной привычки.»,
«Отлично! Все привычки выполнены.», «Сегодня не получилось. Завтра продолжаем.»,
«30 дней подряд — отличная серия!», «Пока недостаточно данных для статистики.»,
«У вас пока нет привычек.»

## Как проверить мобильную и планшетную версию

**Способ 1 — DevTools (быстрый):**

1. Откройте приложение в Chrome: <http://127.0.0.1:8123/>.
2. `F12` → значок телефона/планшета в углу (или `Ctrl+Shift+M`).
3. В строке сверху выберите устройство либо впишите размер:
   * телефон — `360 × 740`, `414 × 896`;
   * планшет — `768 × 1024` (книжный) и `1024 × 768` (альбомный);
   * ноутбук — `1366 × 768`.
4. Пройдите по экранам **Сегодня → Привычки → Категории → форма привычки →
   Календарь → Статистика → Настройки** и проверьте:
   * внизу нет горизонтальной полосы прокрутки;
   * текст, значки и кнопки не вылезают за карточки и за край экрана;
   * открывается бургер-меню, разделы из него переключаются;
   * при ширине меньше 1024px сверху есть шапка с кнопкой «+ Привычка»;
   * галереи на «Привычках» и «Категориях» листаются пальцем или мышью;
   * настройки: карточки одной высоты, кнопки не обрезаны.

**Способ 2 — настоящий телефон:** откройте сайт с телефона в той же сети —
`http://<ip-компьютера>:8123/`. Уведомления и установка PWA работают только
по HTTPS или `http://localhost`, поэтому после публикации удобнее проверять
уже на GitHub Pages.

**Способ 3 — автоматически:**

```bash
node tools/test_layout.js   # 1920 / 1440 / 768 / 360 px: скролл, темы, бургер, PWA
```

### Масштаб на ноутбуках (как окно подстраивается под ширину)

Макет спроектирован под окно шириной **1920 CSS-пикселей**: на 1920×1080
карточки Настроек — ровно 5 штук 389×418 (спека «Правок 6», проверяется).

Ниже 1920 ничего не переключается ступенями — размеры живут в плавных
`clamp()`, у которых максимум достигается ровно на 1920 (коэффициент =
максимум / 19.2). На окне 1540 px (это 1920 при системном масштабе Windows
125%) вы видите те же пропорции, но на ~80%: заголовок «Сегодня» 48 → 38.5,
кольцо прогресса 366 → 294, боковая панель 275 → 230. Между 1920 и 1024
значения идут ровной линией, без «лесенки» и без прыжков; на планшете и
телефоне (`< 1024px`) действуют свои, отдельные правила.

Почему раньше было хуже: масштаб задавался свойством `zoom`, включаемым
ступенями по ширине окна. Зум вкладки браузера тоже меняет ширину окна
в CSS-пикселях, и две величины перемножались — отсюда «80% крупнее 90%»,
«110% крупнее 125%» и скачок на 1920. Теперь свойства `zoom` в вёрстке нет,
а высоты записаны обычными `100vh`/`100dvh`: зум браузера работает как у
обычного сайта — px-шрифты растут, вёрстка перестраивается, инверсий нет.

Замеры на ширинах 1024…2200 px: значения идут монотонно, горизонтального
скролла нет; зум вкладки 67–150% инверсий не даёт («80% крупнее 90%» больше
не встречается). Вёрстка и размеры на 1920 / 1440 / 768 / 360 проверяются
тестом `node tools/test_layout.js` (см. «Способ 3» выше).

## Структура

```
index.html            разметка: экран входа, каркас приложения, модалки, тосты
manifest.webmanifest  манифест PWA
sw.js                 service worker (офлайн-доступ к оболочке)
css/styles.css        дизайн-система, светлая/тёмная тема, адаптив
js/store.js           данные: авторизация, привычки, категории, история, статистика
js/ui.js              модалки, тосты, даты, тема, значки, переводы величин
js/icons.js           линейные значки (генерируется tools/gen_icons_js.py)
js/views.js           экраны приложения
js/app.js             маршрутизация (hash), вход/выход, меню, напоминания, PWA
fonts/                Manrope (woff2, свой хостинг, без внешних запросов)
icons/                SVG + PNG иконки (192/512/maskable)
tools/                скрипты проверок и генерации (см. ниже)
start.cmd             локальный запуск на Windows
```

## Данные и безопасность

* Ключи `localStorage`: `ht:users:v1` (аккаунты), `ht:session:v1` (сессия),
  `ht:data:v1:<userId>` (привычки, категории, история, настройки).
* Пароль хранится только в виде хеша SHA-256 (с солью-логином), в открытом виде не сохраняется.
* История хранится как `YYYY-MM-DD → { habitId: количество }`.
* Экспорт — JSON-файл со всеми привычками, категориями, историей и настройками.
* «Удалить данные» очищает привычки и историю, аккаунт остаётся.
* Данные не покидают устройство: сервера и аналитики нет.

## Проверки

```bash
# синтаксис (Windows PowerShell)
Get-ChildItem js\*.js | ForEach-Object { node --check $_.FullName }

node tools/test_store.js      # логика данных, категорий, пропусков, статистики
node tools/test_ui.js         # смоук-тест всех экранов на jsdom
node tools/diag_listeners.js  # регрессия: повторные заходы не ломают кнопки
node tools/test_layout.js     # настоящий headless Chrome: 1920/768/360, темы, скриншоты
```

* `test_store.js` не требует установки.
* `test_ui.js` требует `jsdom`, поставленный **вне проекта**
  (например `npm i jsdom` во временной папке) — тест сам ищет его
  в `%TEMP%/opencode/uitest/node_modules`.
* `test_layout.js` подключается по CDP к уже запущенному Chrome:
  `chrome --headless=new --remote-debugging-port=9333 --user-data-dir=<папка> about:blank`
  и проверяет фон светлой темы, отсутствие горизонтального скролла на
  1920 / 768 / 360 px, бургер-меню, service worker и манифест;
  скриншоты сохраняются в `%TEMP%/opencode/shots`.

## Публикация на GitHub

**Копировать нужно папку проекта целиком — `tracker.habits`** (то есть её
содержимое): `index.html`, `sw.js`, `manifest.webmanifest`, `README.md`,
`start.cmd`, `.gitignore` и папки `css/`, `js/`, `fonts/`, `icons/`, `tools/`.

1. `.gitignore` уже исключает резервные копии (`Резервная копия_*/`),
   исходный брендбук и рабочие заметки — в репозиторий они не попадут.
2. Все пути внутри проекта **относительные**, поэтому сайт корректно
   работает и во вложенной папке GitHub Pages.
3. Создайте на GitHub пустой репозиторий (без README и `.gitignore` —
   они уже есть в проекте), затем выполните в папке проекта:

```bash
git init
git add .
git commit -m "Ритм — трекер привычек: финальная версия"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

4. Включите публикацию: *Settings → Pages → Deploy from a branch →
   main / (root)* — сайт откроется по адресу
   `https://<user>.github.io/<repo>/`.

> Service worker и уведомления работают по HTTPS (или `http://localhost`).
> На GitHub Pages это обеспечивается автоматически.

## Ограничения

* один пользователь, без сервера и синхронизации между устройствами;
* напоминания срабатывают, пока приложение открыто в браузере (push-сервера нет —
  это честно указано в разделе «Уведомления» в настройках);
* периодичность: «каждый день» и «выбранные дни недели».
